## [1.6.0] - 2026-11-08

### Changed

-   "Tidy up after my birthday" waits for Christmas too: a fulfilled wish leaves the lists once the next birthday or Christmas after it was fulfilled is over (two weeks after the birthday, or at the end of January after Christmas). If the next of these is less than two months away by then, it waits for that one as well
-   Link previews always use the screenshots which come with wishthis (or the default preview)

### Fixed

-   An error dialog covering the login form when a page preview could not be saved in the background
-   Creating or renaming a wishlist with a long name, or saving a long first, last or nick name, failing with "Internal Server Error" or a blank page. Name fields stop at the limit while typing, and the server shortens a name that doesn't fit
-   Bad input to the API (e.g. an id like `abc`, or restoring a deleted wish while logged out) causing a server error instead of "not found"
-   `/wishlist` without a hash, and blog posts that don't exist, causing a server error. They show "Wishlist not found" or go back to the blog
-   The line breaks of wish descriptions being lost in the details dialog
-   Backslashes in list and profile names being shown twice. Names saved before this update keep the doubled backslashes until they are renamed

### Security

-   Anybody could set the link preview of any page to any picture, by pretending to be a crawler. Previews are no longer taken from visitors
-   Files with any content could be written to the server through the link preview screenshot request
-   API modules and pages could be loaded from outside their folders (e.g. with `../`), and the "not found" messages showed the requested name unescaped, so a crafted link could run JavaScript on the site
-   The profile page accepted any section name from the form
-   The web server served the git history, configuration samples, sources, tests, `vendor/` and `node_modules/`, and on SQLite installs the database itself. Only the files browsers need are served now
